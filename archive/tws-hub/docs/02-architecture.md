# 02. Архитектура

## 2.1. Общая блок-схема

```
                          ┌──────────────────────────────────────────┐
   Телефон / планшет ──BT─▶│ SLOT 0   BT-модуль в роли A2DP Sink      │
   (или ТВ по BT)          │ "TWS-HUB"                               │
                          └───────────────┬──────────────────────────┘
   ТВ (оптика/AUX) ─────────────────────▶│  I2S  (BCLK / WS / DATA)
                                         │  или аналог L+R
                          ┌──────────────┴──────────────────────────┐
                          │         АУДИОШИНА (общий клок)          │
                          └──┬───────────┬───────────┬──────────────┘
                             │           │           │
                     ┌───────▼──┐ ┌──────▼───┐ ┌─────▼─────┐
                     │ SLOT 1   │ │ SLOT 2   │ │ SLOT N    │
                     │A2DP Source│ │A2DP Source│ │A2DP Source│
                     └────┬─────┘ └────┬─────┘ └─────┬─────┘
                       BT │         BT │          BT │
                          ▼            ▼             ▼
                      Колонка 1    Колонка 2     Колонка N

   ┌───────────────────────────────────────────────────────────┐
   │ ARDUINO (Nano Every / Nano / Uno)                         │
   │   UART ──▶ 74HC4051 #1 (демux 1:8) ──▶ RX модулей         │
   │   RX  ◀── 74HC4051 #2 (mux 8:1)  ◀── TX модулей           │
   │        линии S0/S1/S2 выбирают слот (до 8 штук)           │
   │   I2C ──▶ OLED SSD1306 128x64 + PCF8574 (питание слотов)  │
   │   GPIO ─▶ 5 кнопок, светодиод, пищалка                    │
   │   EEPROM ─▶ список колонок (MAC, имя, канал, trim)        │
   └───────────────────────────────────────────────────────────┘
```

Обратите внимание: **звук и управление идут разными путями**. Arduino
вообще не касается аудио — она только «щёлкает» BT-модули командами.

## 2.2. Почему один UART на восемь модулей

У ATmega328P один аппаратный UART, и он занят USB-отладкой. У ATmega4809
(Nano Every) тоже по факту доступен один `Serial1`.

Решение — **аналоговый мультиплексор 74HC4051**:

* первая микросхема работает **демультиплексором**: общий TX ардуино
  подаётся на вход Z и коммутируется на один из восьми выходов Y0..Y7,
  то есть на RX нужного модуля;
* вторая — **мультиплексором**: TX модулей приходят на Y0..Y7, выбранный
  канал выходит на Z и идёт в RX ардуино;
* обе управляются одними и теми же тремя линиями S0/S1/S2.

```
      Arduino TX ──[level shift 5V→3V3]──▶ 74HC4051 #1 ──▶ RX слотов 0..7
                                          (как 1:8 демux)
      Arduino RX ◀──[74HCT125 3V3→5V]──── 74HC4051 #2 ◀── TX слотов 0..7
                                          (как 8:1 mux)
                    S0, S1, S2 ─────────▶ обе микросхемы
```

74HC4051 — двунаправленный аналоговый ключ, полоса у него единицы МГц,
так что UART на 115200 проходит без вопросов.

Если вам лень ставить мультиплексоры: можно подключить TX ардуино
**параллельно** на все модули сразу (все они получат одну команду), но
тогда вы не сможете читать ответы — придётся работать вслепую. Вариант
«один модуль на один UART» возможен только на Arduino Mega 2560 (4 UART).

## 2.3. Четыре топологии

Прошивка поддерживает четыре режима; выбираются в меню
`MENU → Topology` или по Serial (`0`..`3`).

### TOPO_DUAL — «две колонки, синхронно»

```
Phone ─BT─▶ SLOT0 (sink) ══I2S══▶ SLOT1 (source, dual-link) ══▶ Колонка L
                                                            ══▶ Колонка R
```

Один чип (SLOT1) держит оба линка от одного клока → рассинхрон единицы мс.
**Это лучший выбор для стереопары в одной комнате.**

Ограничение: SLOT1 должен уметь dual-link. Проверяйте перед покупкой
(см. [03-bom.md](03-bom.md)).

### TOPO_MULTI — «N колонок, best effort»

```
Phone ─BT─▶ SLOT0 (sink) ══общая I2S-шина══┬─▶ SLOT1 ─BT─▶ Колонка 1
                                           ├─▶ SLOT2 ─BT─▶ Колонка 2
                                           └─▶ SLOT3 ─BT─▶ Колонка 3
```

Общий I2S-клок гарантирует, что **кодирование** начинается на одном и том
же сэмпле у всех модулей. Но джиттер-буфером каждой колонки управляет сама
колонка → начальный сдвиг случаен.

* **Для мультирума (разные комнаты) — отлично.**
* **Для одной комнаты — эхо.** Подробный расчёт в [05](05-sync-and-latency.md).

Частично поможет: выставить **один и тот же кодек** на всех линках
(`AT+A2DPCFG=`), чтобы глубины буферов были сопоставимы. Убирает часть
разброса, но не гарантирует синхрон.

### TOPO_PARTY — «цепочка вендора»

```
Phone ─BT─▶ SLOT0 (sink) ══▶ SLOT1 ─BT─▶ Мастер-колонка ─ party ─▶ +1
                                                        └ party ─▶ +2 ...
```

Хаб подключается только к мастер-колонке; дальше синхронизацией занимается
PartyBoost / PartyCast / Party Chain / SimpleSync. Синхронность —
вендорская, зато на сколько угодно колонок.

Для Arduino это самый простой режим: поднимается ровно один линк.

### TOPO_AURACAST — «LE Audio, сколько угодно приёмников»

```
Phone ─BT─▶ SLOT0 (sink / линейный вход) ══▶ Auracast-передатчик (BIS)
                                                   │
                            ┌──────────────────────┼──────────────────┐
                            ▼                      ▼                  ▼
                     Auracast-колонка      Приёмник+AUX         Смартфон-слушатель
```

Правильный путь, если колонки (или приёмники при них) умеют Auracast.
Один закодированный поток, все слушатели синхронны
[3](https://www.soundcore.com/blogs/speaker/what-is-auracast).

## 2.5. Разделение обязанностей в прошивке

| Файл | Отвечает за |
|---|---|
| `config.h` | выбор платы, пины, тайминги, битовые маски профилей |
| `log.h/.cpp` | Serial-лог, формат из flash, работа с MAC-адресами |
| `bt_bus.h/.cpp` | один UART + мультиплексор: выбор слота, отправка AT, чтение строки |
| `bt_slot.h/.cpp` | жизненный цикл модуля: Probe → Role → Connect → StartAudio |
| `speaker_db.h/.cpp` | список колонок в EEPROM с CRC-8 |
| `buttons.h/.cpp` | 5 кнопок: клик, длинное нажатие, автоповтор |
| `audio_core.h/.cpp` | оркестрация подключений, конечный автомат без блокировок |
| `ui.h/.cpp` | примитивы вывода на OLED |
| `menu.h/.cpp` | экраны и навигация |
| `tws_hub.ino` | `setup()` / `loop()` + отладочный Serial-CLI |

Конечный автомат в `audio_core.cpp` **не блокирует** `loop()`: каждый вызов
`audioCoreTick()` делает один шаг (послать команду / прочитать строку /
проверить таймаут), поэтому меню продолжает реагировать на кнопки, пока
идёт подключение.

## 2.6. Питание и «горячее» включение модулей

Каждый BT-модуль потребляет 20–60 мА в пике. Восемь модулей — до 0.5 А,
плюс Arduino и дисплей. Берите блок **5 В / 2 А** с запасом.

Полезная доработка: запитать слоты через P-канальные MOSFET, затворами
которых рулит PCF8574 по I2C. Тогда прошивка сможет:

* перезагружать «зависший» модуль, сняв с него питание на 500 мс;
* отключать неиспользуемые слоты для экономии;
* включать модули по очереди, чтобы не сажать шину 3.3 В стартовым
  броском тока.

В базовой версии можно обойтись без этого — просто подайте 3.3 В на все
модули постоянно.
