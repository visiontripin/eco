# 08. Пошаговый запуск

Порядок важен. Не переходите к следующему шагу, пока предыдущий не дал
ожидаемый результат — иначе будете искать аппаратную проблему в коде.

## Шаг 0. Проверка прошивки без железа

```bash
cd archive/tws-hub/tools/host_check
./check.sh
```

Ожидается: `== OK: синтаксис и типы в порядке ==`.
Если нет — исправьте до сборки железа.

## Шаг 1. Один BT-модуль на столе

**Не подключайте Arduino.** Возьмите USB-UART на 3.3 В.

```
  USB-UART 3V3 ──▶ VDD
  USB-UART GND ──▶ GND
  USB-UART TX  ──▶ UART_RX (pin 14)
  USB-UART RX  ◀── UART_TX (pin 13)
```

Терминал: 115200, 8N1, «оба конца строки» (CR+LF).

| Отправить | Ожидаемый ответ |
|---|---|
| `AT` | `OK` |
| `AT+VER` | `+VER=BT1036,V2.6.1,20220922` |
| `AT+HELP` | сводка по функциям |
| `AT+PROFILE` | `+PROFILE=1195` |

**Критерий успеха:** модуль отвечает `OK` на `AT`.

**Если молчит:** переберите скорости 9600, 19200, 38400, 57600, 115200.
Заодно сразу переведите модуль на удобную скорость (`AT+BAUD=9600` для
Nano/Uno с SoftwareSerial) — так проще жить дальше.

**Если отвечает мусором:** неверная скорость.

## Шаг 2. Проверить, что модуль умеет A2DP Source

```
  >> AT+PROFILE=339
  << OK                 (модуль перезагружается, ждём ~1.2 с)
  >> AT
  << OK
  >> AT+PROFILE
  << +PROFILE=339       ← если вернул 1195 или другое — прошивка не даёт
                          включить A2DP Source. Меняйте модуль.
```

**Критерий успеха:** `+PROFILE=339` и модуль жив после смены профиля.

Это самый важный шаг. Если он провалился, вся `TOPO_MULTI`/`TOPO_DUAL`
невозможна в принципе.

## Шаг 3. Проверить dual-link (только для TOPO_DUAL)

```
  >> AT+SCAN=1
  << +SCAN=<MAC1>,-45,Speaker A
  << +SCAN=<MAC2>,-52,Speaker B
  >> AT+SCAN=0
  >> AT+A2DPCONN=<MAC1>
  << OK
  << +A2DPSTAT=3
  >> AT+A2DPAUDIO=1
  << OK
  << +A2DPSTAT=5
  >> AT+A2DPCONN=<MAC2>      ← пробуем ВТОРУЮ, не разрывая первую
  << OK                       ← если OK и пришло +A2DPSTAT=3/5 по второму
                                линку — dual-link есть
```

**Критерий успеха:** два линка одновременно, обе колонки играют.
Если модуль разорвал первый линк — dual-link **нет**, используйте
`TOPO_PARTY` или `TOPO_AURACAST`.

## Шаг 4. Arduino + дисплей (без BT)

Подключите только OLED. Залейте прошивку.

**Критерий успеха:** на экране `TWS-HUB v0.4` и статус, в Serial Monitor
(115200) — приветствие и `ready. press 'h' for CLI`.

Если дисплей пустой: проверьте адрес I2C (0x3C или 0x3D) и подтяжки SDA/SCL.

## Шаг 5. Arduino + один BT-модуль

Подключите SLOT0 напрямую (без мультиплексора): TX→RX, RX→TX,
через преобразователь уровней.

В Serial Monitor нажмите `p` (probe all slots).

```
  probe slot 0 -> OK
  probe slot 1 -> no answer
  ...
```

**Критерий успеха:** слот 0 отвечает.

Если «no answer» — проверьте: 3.3 В, общую землю, TX/RX не перепутаны,
скорость в `config.h` (`BT_BAUD`) совпадает с модулем.

## Шаг 6. Мультиплексор

Подключите обе 74HC4051, линии S0/S1/S2, слоты 0 и 1.
В Serial Monitor снова `p`.

**Критерий успеха:** слоты 0 и 1 отвечают, остальные — «no answer».

Если отвечает только один или «перекрёстно» — проверьте распиновку
S0/S1/S2 и что `/E` посажен на GND.

## Шаг 7. Аудиошина

Соедините I2S (или аналог) от SLOT0 к SLOT1..N.
Настройте:

* SLOT0: `AT+I2SCFG=1` (master);
* SLOT1..N: `AT+I2SCFG=3` (slave).

Проверьте осциллографом или логическим анализатором: BCLK = 1.536 МГц,
WS = 48 кГц.

## Шаг 8. Первое подключение колонки

В Serial Monitor:

* `s` — поиск. Должны посыпаться `found <MAC>  <name>`.
* `l` — подключение. Смотрите лог:

```
  [I] link all: 2 target(s)
  [I] slot 1 -> AABBCCDDEEFF (JBL Flip 6)
  [I] slot 1 streaming, codec=SBC
  [I] link plan finished: 2/2 ok, streaming=2
```

**Критерий успеха:** колонка заиграла, в логе `streaming`.

## Шаг 9. Меню

* `OK` — войти в меню;
* `Speakers → < scan/add >` — поиск и добавление;
* `Connect all` — поднять все линки;
* `Topology` — выбрать топологию.

**Критерий успеха:** колонка добавляется в EEPROM и появляется в списке
после перезагрузки (проверьте командой `d` в CLI).

## Шаг 10. Измерение рассинхрона

По методике из [05](05-sync-and-latency.md#56-как-измерить-рассинхрон-практически).

| Результат | Что делать |
|--:|---|
| Δt < 1 мс | всё отлично, так и оставить |
| 1–5 мс | хорошо для одной комнаты |
| 5–35 мс | для одной комнаты плохо → переходить на DUAL / PARTY / AURACAST |
| > 35 мс | только мультирум |

## Тестовый чек-лист

- [ ] `AT` отвечает на всех слотах (`p` в CLI)
- [ ] A2DP Source включается (`+PROFILE=339`)
- [ ] Dual-link подтверждён (для `TOPO_DUAL`)
- [ ] I2S клоки присутствуют (BCLK 1.536 МГц, WS 48 кГц)
- [ ] Колонка подключается и играет (`streaming` в логе)
- [ ] Список колонок сохраняется в EEPROM (команда `d` после ребута)
- [ ] Кнопки работают, меню листается
- [ ] Дисплей гасится через 30 с
- [ ] Δt между колонками измерен и укладывается в ожидания
- [ ] Задержка от источника измерена (для ТВ — критично)
- [ ] БП не греется, 3.3 В не просаживается ниже 3.2 В под нагрузкой

## Что делать, если «ничего не работает»

1. Вернитесь к шагу 1. 90 % проблем — питание, уровни или скорость UART.
2. Посмотрите лог на скорости DEBUG (`TWSHUB_DEBUG 1` в `config.h`):
   там видны все `s<n> <- команда` и `s<n> -> ответ`.
3. Подключите логический анализатор к TX/RX Arduino и к RX/TX модуля —
   сразу увидите, уходит ли команда и приходит ли ответ.
4. Проверьте, что модуль в слоте не в режиме прозрачной передачи:
   `AT+TPMODE=0`.
