# 10. Ваша конфигурация: итоговый план

## 10.1. Исходные данные

| Параметр | Значение | Следствие |
|---|---|---|
| Колонок | **3–5, в одной комнате** | рассинхрон будет слышен → независимые A2DP-линки **отпадают** |
| Бренды | **разные**, часть с AUX, часть только BT | вендорский party-режим **отпадает** |
| Источник | **ТВ и телефон**, задержка критична | SBC (~400 мс) **отпадает** |
| Плата | Arduino **Nano (ATmega328P)** | 2 КБ ОЗУ, SoftwareSerial → экономим память |

## 10.2. Вердикт

> **Единственная технология, которая закрывает все четыре требования
> одновременно — Auracast (LE Audio, BIS).**

| Технология | 3–5 в одной комнате | Разные бренды | Низкая задержка |
|---|:--:|:--:|:--:|
| N независимых A2DP-линков (`TOPO_MULTI`) | ❌ эхо | ✅ | ❌ |
| Dual-link (`TOPO_DUAL`) | ❌ только 2 | ✅ | ⚠️ нужен aptX-LL |
| Party-режим вендора (`TOPO_PARTY`) | ✅ | ❌ | ⚠️ |
| **Auracast (`TOPO_AURACAST`)** | ✅ | ✅ | ✅ 20–50 мс |

Auracast — это **Broadcast Isochronous Stream**: передатчик кодирует звук
один раз и рассылает один поток по единой временной сетке, любое число
приёмников синхронизируется по одной передаче
[5](https://moschip.com/blog/device-software-engineering/what-is-auracast-and-how-it-helps-bluetooth-le-audio-enabled-broadcast/).
Плюс LC3 вместо SBC — задержка падает с ~200 мс до 20–50 мс, что решает
вашу проблему с ТВ.

## 10.3. СНАЧАЛА ПРОВЕРЬТЕ ЭТО (бесплатно)

Прежде чем что-то покупать:

1. **Посмотрите спецификации ваших колонок на слова «Auracast» / «LE Audio».**
   Модели 2025–2026 годов этим всё чаще умеют. Если у 2–3 колонок Auracast
   уже есть — вам не нужны приёмники, стоимость падает втрое.

2. **Проверьте телефон.** Samsung (Galaxy S23+) и часть Android-флагманов
   умеют вещать Auracast напрямую («Настройки → Bluetooth → Auracast» или
   «Поделиться звуком»). Если да — можно прямо сегодня проверить,
   подхватывают ли колонки ваш поток, вообще ничего не покупая.

3. **Уточните, у каких именно колонок есть AUX-вход.** Именно под них
   покупаются Auracast-приёмники.

## 10.4. Рекомендуемая схема (План A)

```
   ТВ (оптика или AUX) ──────────────┐
                                     │
                              ┌──────▼───────┐
   Телефон ──Bluetooth──▶ SLOT0│  реле 2:1   │
                    FSC-BT1036C│  источника   │  ← переключает Arduino
                    (A2DP Sink) └──────┬───────┘
                                       │ AUX
                              ┌────────▼─────────┐
                              │ Auracast-передатчик│  Avantree Audikast 4
                              │  (LC3, BIS)       │  вход: оптика + AUX
                              └────────┬─────────┘
                                       ║  один поток, сколько угодно слушателей
                    ┌──────────────────╬──────────────────┐
                    ▼                  ▼                  ▼
             ┌────────────┐     ┌────────────┐     ┌────────────┐
             │ Auracast-  │     │ Auracast-  │     │ Колонка с  │
             │ приёмник   │     │ приёмник   │     │ Auracast   │
             │ (AuraLink) │     │ (AuraLink) │     │  из коробки│
             └─────┬──────┘     └─────┬──────┘     └────────────┘
                   │ AUX              │ AUX
                   ▼                  ▼
              Колонка 1          Колонка 2

   Arduino Nano: дисплей, кнопки, переключение источника,
                 список колонок в EEPROM, индикация состояния
```

**Обратите внимание, что изменилось.** В этой схеме хабу **не нужны**
передатчики на каждую колонку, а значит не нужны и обе 74HC4051, и восемь
BT-модулей, и преобразователь уровней на 8 линий. Остаётся:

* **Arduino Nano** — мозг и интерфейс;
* **один FSC-BT1036C** — Bluetooth-приёмник для телефона (SLOT0);
* **Auracast-передатчик** — вещает поток;
* **реле 2:1** — выбор источника (ТВ или телефон), им рулит Arduino;
* **Auracast-приёмник на каждую колонку, у которой нет Auracast**.

Это радикально проще и дешевле, чем «8 модулей + мультиплексоры».

## 10.6. Поэтапный путь (чтобы не выбросить деньги)

**Этап 0 — собрать ядро за $60.** Nano + 2 модуля + мультиплексоры,
топология `TOPO_DUAL`, две колонки. Убедиться, что всё работает, измерить
задержку и рассинхрон по [05](05-sync-and-latency.md#56-как-измерить-рассинхрон-практически).
Этот этап ценен сам по себе: вы получите понимание, как модули отвечают.

**Этап 1 — пилот Auracast за $147.** Один AuraLink ($67) + Audikast 4 ($80).
Проверить синк на 2–3 колонках и померить реальную задержку для ТВ.

**Этап 2 — масштабирование.** Докупить AuraLink на остальные колонки.

**Если на этапе 1 окажется, что ваши колонки уже умеют Auracast** — этапы
сворачиваются в покупку одного Audikast 4 за $80, и хаб превращается в
пульт с дисплеем.

## 10.7. Честное замечание про «готовый бокс»

Avantree **Oasis Aura** ($129) принимает Bluetooth, оптику и AUX и сам
вещает Auracast
[3](https://avantree.com/collections/auracast-transmitters). То есть
задача «ТВ + телефон → 5 колонок синхронно» решается одной коробкой без
пайки.

Смысл вашего проекта на Arduino — не в том, чтобы «сделать как в коробке»,
а в том, чтобы получить то, чего в коробке нет:

* список колонок **с именами** и индивидуальное включение/выключение;
* запоминание конфигурации в EEPROM;
* автоматический выбор источника (ТВ / телефон) по наличию сигнала;
* индикация: сколько колонок реально играет, какой кодек, какая задержка;
* автопереподключение и диагностика;
* ну и просто интересно разобраться.

Если вам нужен **результат, а не процесс** — берите Oasis Aura.
Если интересен проект — делайте по Плану A.

## 10.8. Что уже изменено в прошивке под вашу конфигурацию

| Изменение | Файл | Зачем |
|---|---|---|
| `TWSHUB_BOARD` по умолчанию = `BOARD_NANO_CLASSIC` | `config.h` | ваша плата |
| UART: SoftwareSerial D7/D8, **9600 бод** | `config.h` | у 328P аппаратный UART занят USB |
| Добавлен `BOARD_NANO_HWUART` | `config.h` | если нужен 115200 — BT-шина на D0/D1, отладка жертвуется |
| `MAX_SPEAKERS` = **8** для 328P (16 для Every/Mega) | `config.h` | экономия 224 байт ОЗУ |
| `BT_LINE_MAX` 80 → **64** | `config.h` | экономия стека |
| Буфер лога 110 → **80**, печать вырезается при `TWSHUB_DEBUG=0` | `log.cpp` | экономия flash и 200 байт стека |
| `TWSHUB_DEFAULT_TOPO` = **3 (AURACAST)** | `config.h` | ваша топология по умолчанию |
| `freeRam()` переписан через `ptrdiff_t` | `menu.cpp` | корректно и на AVR, и при проверке на хосте |
| Проверка собирает **все 5 вариантов плат** | `check.sh` | `BOARDS="1 2 3 4 5" DEEP=1 ./check.sh` |

**Оценка ОЗУ (ATmega328P):** ~450 байт статики (база 8×28 = 224, слоты
8×12 = 96, кнопки, состояние) + ~300 байт стека. Из 2048 — влезает
с запасом.

**Если прошивка не влезет во flash (32 КБ):** поставьте в `config.h`
`TWSHUB_DEBUG 0` — это высвободит 2–3 КБ (`vsnprintf_P` + строки лога)
и ~200 байт стека. Serial-CLI при этом отключится.

## 10.10. Открытый вопрос

Вы указали «разные бренды, часть с AUX, часть только Bluetooth». Для
**BT-only колонок без Auracast** честных вариантов два:

1. **Заменить** их на модели с Auracast (или хотя бы с AUX-входом, тогда
   они работают через AuraLink);
2. **Вынести в другие комнаты** — там рассинхрон не слышен, и они
   нормально работают на независимых A2DP-линках.

Оставить BT-only колонку без Auracast в одной комнате с остальными и
получить синхронный звук — **нельзя никак**. Это ограничение самой
технологии, а не вашей схемы.
