# 05. Задержки и синхронизация: расчёт

Это самая важная глава. Здесь объясняется, откуда берутся миллисекунды и
почему их нельзя «просто скомпенсировать в коде».

## 5.1. Из чего складывается задержка связки «источник → колонка»

```
  PCM ─▶[энкодер]─▶[RTP/L2CAP]─▶[эфир+ретрансмиты]─▶[джиттер-буфер]─▶[декодер]─▶[ЦАП]─▶ звук
   │       (1)          (2)            (3)                (4)            (5)      (6)
```

| Этап | SBC | AAC | aptX | aptX-LL | LDAC | LC3 (Auracast) |
|---|--:|--:|--:|--:|--:|--:|
| 1. Энкодер (накопление кадра) | 10–40 | 20–40 | 1–2 | 1 | 20–35 | 10 |
| 2. Пакетирование, RTP/L2CAP | 5–15 | 5–15 | 5–15 | 5–10 | 5–15 | 2–5 |
| 3. Эфир, ретрансмиты | 5–40 | 5–40 | 5–30 | 5–20 | 10–50 | 5–40 |
| 4. **Джиттер-буфер приёмника** | **100–250** | **100–200** | **40–80** | **30–40** | **100–200** | **10–40** |
| 5. Декодер | 2–5 | 5–10 | 1–2 | 1 | 5–10 | 3–5 |
| 6. ЦАП + усилитель | 2–10 | 2–10 | 2–10 | 2–10 | 2–10 | 2–10 |
| **Итого, типично** | **~200** | **~180** | **~90** | **~40** | **~200** | **~35** |

(все значения в миллисекундах, ориентировочно)

Главный вклад — **джиттер-буфер приёмника (строка 4)**, и именно он
**не управляется источником**.

Ориентиры для реальных устройств: MoerLab TV hearMore заявляет < 60 мс в
режиме Auracast и < 40 мс в режиме FastStream
[4](https://www.moor-audio.com/products/tvhearmore-bluetooth-auracast-audio-transmitter);
Avantree HT4189 — < 40 мс
[4](https://avantree.com/products/ht4189-bluetooth-tv-headphone-transmitter-set).

## 5.2. Сколько задержки терпимо

### Для видео (губы ↔ звук)

По ITU-R BT.1359-1 порог **заметности** рассинхрона звук/видео: звук может
отставать до **125 мс** и опережать до **45 мс**, прежде чем зритель это
заметит; порог **приемлемости** — −185 / +90 мс.

Практические рекомендации:

| Задержка | Оценка |
|--:|---|
| < 20 мс | не заметно |
| 20–40 мс | незаметно большинству, комфортно |
| 40–100 мс | заметно, при видео раздражает |
| 100–200 мс | очень заметно, нужна компенсация в ТВ |
| > 200 мс | некомфортно |

**Вывод для ТВ:** SBC (~200 мс) — это «звук опоздал», голова будет
перекошена. Берите модуль с aptX-LL/aptX-Adaptive или Auracast, либо
включите компенсацию задержки в настройках ТВ/плеера (во многих ТВ есть
«Audio Delay / Lip Sync», 0–250 мс с шагом 10 мс).

### Для музыки

Задержка звука относительно источника **безразлична** (вы всё равно не
сравниваете с видео). Важна только **разница между колонками**.

## 5.3. Рассинхрон между колонками: математика

### Независимые линки (TOPO_MULTI)

Пусть глубина джиттер-буфера колонки = `B` мс, а момент старта буфера
равномерно распределён в интервале `[0, B]`. Для двух независимых колонок:

```
  Δt = t_1 − t_2  — случайная величина
  M[|Δt|] = B/3          (математическое ожидание модуля разности)
  P(|Δt| > 0.5·B) ≈ 0.25
```

| Кодек | B, мс | Ожидаемый Δt, мс | Худший случай, мс |
|---|--:|--:|--:|
| SBC | 200 | ~67 | 200 |
| aptX | 80 | ~27 | 80 |
| aptX-LL | 40 | ~13 | 40 |
| LC3 (Auracast) | 30 | ~10 | 30 |

**67 мс между двумя колонками в одной комнате — это слышимое эхо.**

### Дрейф во времени

Такт ЦАП колонки и такт пикосети не синхронизированы. Разница в частотах
`δ` (ppm) даёт скорость расхождения:

```
  dΔt/dt = δ  мкс/с

  δ = 20 ppm  →  0.072 мс/мин  →   4.3 мс/час
  δ = 50 ppm  →  0.180 мс/мин  →  10.8 мс/час
  δ = 100 ppm →  0.360 мс/мин  →  21.6 мс/час
```

A2DP передаёт RTP-таймстемпы, поэтому «хорошая» колонка держит буфер на
постоянном уровне и дрейф компенсирует сама. «Дешёвая» — либо плавает,
либо сбрасывает/вставляет сэмплы (щёлчки).

### Пороги слышимости

| Δt между колонками | Что слышно |
|--:|---|
| < 0.5 мс | ничего |
| 0.5–1 мс | появляется гребенчатый фильтр (comb filtering) |
| 1–10 мс | заметная окраска тона, «бубнение», пропадает стереобаза |
| 10–35 мс | эффект Хааса: локализация по первой колонке + окраска |
| 35–50 мс | начинает восприниматься как эхо |
| > 50 мс | два раздельных источника, «вразнобой» |

Практический ориентир: **в одной комнате нужно Δt < 5 мс**, комфортно
< 1 мс. Ни один набор независимых A2DP-линков этого не даёт.

## 5.4. Что реально даёт синхронность

### Один чип на все линки (TOPO_DUAL, TOPO_PARTY)

Источник формирует оба потока **от одного аудиоклока** и планирует их
передачу в одном таймлайне. Разница остаётся только за счёт разной глубины
буферов приёмников, но чип это учитывает — на практике получаются
**единицы миллисекунд**, что ниже порога слышимости окраски.

### Auracast / LE Audio (TOPO_AURACAST)

BIS — это изохронная широковещательная передача: один закодированный поток
с **единой временной сеткой**, все приёмники синхронизируются по одной и
той же передаче [5](https://moschip.com/blog/device-software-engineering/what-is-auracast-and-how-it-helps-bluetooth-le-audio-enabled-broadcast/).
Рассинхрон определяется только разницей хода звука до ушей слушателя
(~3 мс на метр), то есть архитектурно его нет вообще.

## 5.5. Можно ли «подкрутить» независимые линки

Коротко: **нет**, тремя способами, которые обычно предлагают, — нельзя.

| Идея | Почему не работает |
|---|---|
| «Задержать аудио на быстром линке» | Источник не управляет буфером приёмника. У доступных модулей нет AT-команды «подожди 45 мс» |
| «Переподключать, пока не совпадёт» | Δt случаен при каждом подключении, а дрейф всё равно «уедет» за минуты |
| «Подать звук с общей I2S-шины — и будет синхронно» | Общий клок синхронизирует **момент кодирования**, а не момент воспроизведения. Буфер приёмника по-прежнему свой |

Что **можно** сделать, чтобы стало лучше (но не идеально):

1. **Один и тот же кодек на всех линках** (`AT+A2DPCFG=...`). Одинаковая
   глубина буфера уменьшает разброс.
2. **Одинаковые колонки** одной модели и прошивки.
3. **Одновременный старт** — посылать `AT+A2DPCONN` на все слоты с
   минимальным разбросом по времени.
4. **Разнести колонки по комнатам** — тогда рассинхрон не слышен в принципе.

## 5.6. Как измерить рассинхрон (практически)

**Способ 1. Диктофон + Audacity (простой, точность ~1 мс).**

1. Записать трек-«щелчок»: 40 мс тона 1 кГц с паузой 1 с.
2. Поставить диктофон/смартфон на равном расстоянии от колонок.
3. Записать 20–30 с.
4. Открыть в Audacity, найти пары импульсов, измерить разницу по шкале
   времени.

**Способ 2. Два микрофона + двухканальная запись (точность ~0.02 мс).**
Каждый микрофон — у своей колонки. Разница прихода импульсов = Δt.

**Способ 3. «Clap test» на слух.**
Включить короткий импульс. Если слышен «двойной удар» — Δt > 35 мс.
Если звучит «бочкообразно», глухо — Δt ≈ 1–10 мс (comb filtering).

**Что считать успехом:**

| Результат | Вердикт |
|--:|---|
| Δt < 1 мс | отлично (dual-link / Auracast) |
| 1–5 мс | хорошо, для одной комнаты достаточно |
| 5–35 мс | слышна окраска; для одной комнаты — плохо |
| > 35 мс | эхо; использовать только для мультирума |

## 5.7. Сводка по топологиям

| Топология | Задержка от источника | Δt между колонками | Для одной комнаты |
|---|--:|--:|:--:|
| TOPO_DUAL | 40–250 мс | 1–5 мс | ✅ |
| TOPO_MULTI | 40–250 мс | 15–200 мс | ❌ (но ✅ для мультирума) |
| TOPO_PARTY | 50–250 мс | вендорский, обычно < 5 мс | ✅ |
| TOPO_AURACAST | 20–50 мс | < 1 мс | ✅ |
